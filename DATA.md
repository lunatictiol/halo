# DATA.md — dataset formats, as actually inspected

Source: [vectara/open_ragbench](https://huggingface.co/datasets/vectara/open_ragbench), path `pdf/arxiv/`. Fetched by `scripts/download_data.py` into `data/` (gitignored). Every fact below was checked by `scripts/audit_data.py` (output: `results/m0_audit.txt`).

## Files

| File | Shape | Count |
|---|---|---|
| `data/hf/queries.json` | `{query_id: {"query": str, "type": "abstractive"\|"extractive", "source": modality}}` | 3,045 |
| `data/hf/answers.json` | `{query_id: str}` (reference answer) | 3,045 |
| `data/hf/qrels.json` | `{query_id: {"doc_id": str, "section_id": int}}` | 3,045 |
| `data/hf/pdf_urls.json` | `{doc_id: "https://arxiv.org/pdf/<doc_id>"}` | 1,000 |
| `data/hf/corpus/<doc_id>.json` | `{id, title, authors[], categories[], abstract, published, updated, sections: [{section_id: int, text: str}]}` | 1,000 |
| `data/pdfs/<doc_id>.pdf` | arXiv PDF | 1,000 |

**IDs.** `query_id` is a UUID string. `doc_id` is a versioned arXiv ID (`2410.14077v2`); it is the corpus filename stem, the PDF filename stem, and the key of `pdf_urls.json`. `queries`, `answers` and `qrels` have identical key sets.

**Modality (`source`).** Four values: `text` (1,914), `text-image` (763), `text-table` (148), `text-table-image` (220). Type: `abstractive` 1,793, `extractive` 1,252.

## qrels format

Exactly **one relevant section per question** (no graded relevance, no multiple positives). `section_id` refers to Vectara's own markdown parse of the paper in `corpus/<doc_id>.json`:

- In every corpus doc, `section_id`s are `0..n-1` in list order, so `sections[section_id]` is the relevant section (true for all 3,045 qrels).
- Every qrels `section_id` exists in its doc.
- Section text is markdown with headings (`## I. INTRODUCTION`, `#### Abstract`, …) and LaTeX math. Sections per doc: min 0, median 16, max 198.

Real example:

```json
// qrels.json
"852703f0-8373-43a2-a18a-eb5908ad0779": {"doc_id": "2410.14077v2", "section_id": 1}
// queries.json
"852703f0-8373-43a2-a18a-eb5908ad0779": {"query": "What are the challenges in estimating output impedance in inverter-based grids?", "type": "abstractive", "source": "text-image"}
// corpus/2410.14077v2.json -> sections[1].text (first 120 chars)
"## I. INTRODUCTION\n\nThe rapid expansion of distributed energy resources (DERs) and inverter-based loads has made inverter-based..."
```

**Implication for M1.** We parse PDFs ourselves (PyMuPDF), so our chunks have no Vectara section IDs. M1 must map each chunk to a `(doc_id, section_id)` — e.g. by text overlap with the corpus section texts — and report unmapped qrels.

## Corpus composition

- 1,000 papers: **396 source papers** (the `doc_id`s that appear in qrels) + **604 distractors** (no questions).
- Questions per source paper: min 1, mean 7.69, max 10.
- 3 corpus docs have an empty `sections` list. All 3 are distractors and none is in `dev_slice`; irrelevant to qrels because we parse PDFs ourselves.

## Discrepancy with the original local files

The repo started with a third-party repackaging: `Eval_data.csv` (3,045 Q&A rows) and `All_PDFs.csv` (1,001 PDFs = 396 source + 605 distractors). Audit findings:

- `Eval_data.csv` query IDs match HF exactly (3,045/3,045), but it carries **no section-level qrels**.
- Only **19 of its 605 distractors** are among Vectara's official 604. The other ~586 were added by the repackager with unknown selection.

We use the **official** 1,000-paper set (see DECISIONS.md D1). That is why CLAUDE.md says 1,000 papers, not 1,001.

## Splits

Generated by `scripts/make_splits.py` (seed and sizes in `config/default.toml`), committed in `splits/`. Each file: `{name, seed, inputs_sha256, paper_ids[], query_ids[], ...}`, sorted, `json.dumps(indent=2, sort_keys=True)`. `make_splits.py --check` regenerates in memory and byte-compares. Stats: `results/m0_splits_report.txt`.

| Split | Contents |
|---|---|
| `held_out` | 20 source papers never indexed |
| `abstention_set` | 152 questions of the held-out papers (correct behaviour: abstain) |
| `dev_slice` | 103 papers = 43 source + 60 distractors (all 60 share a primary arXiv category with a dev source) |
| `dev_sample` | 303 questions = all questions of the 43 dev source papers |
| `full` | 2,893 answerable questions (3,045 − 152); index = 980 papers |
